Try it without connecting Odoo

Download and extract the v0.2.0 package. You’ll need Node.js 24 or newer. In the extracted folder, run:

npm ci
npm run demo

Open http://127.0.0.1:8787/dashboard. The local demo has fictional records, stores changes in memory and cannot accept real Odoo credentials.

Before connecting real work

Odoo 19

An instance where you can install the included Work Assistant addon. Project and Timesheet capabilities appear when those apps are installed.

A deployed connector

Node.js 24+, HTTPS hosting, an OAuth provider, protected credential storage and approved Odoo hostnames.

Your own Odoo access

A personal Odoo API key with appropriate permissions. A bot key acts as that bot; it does not impersonate your human account.

Other Odoo versions need compatibility testing. Environments that prohibit custom addons need a separate reviewed integration. Check API availability and deployment policies before proceeding.

Connect a staging instance first

  1. Install the Odoo addon

    Add odoo_addons/odoo_work_assistant to the Odoo 19 addons path, restart Odoo, update the Apps list and install Odoo Work Assistant. It depends only on base.

  2. Configure and deploy the connector

    Start from .env.example. Set the real HTTPS URL, OAuth issuer and audience, encryption key, persistent data directory and exact allowed Odoo hostnames. Follow docs/deployment.md in the download.

    npm ci
npm run build
npm start

  3. Connect through the secure setup page

    Open your deployed connector’s /setup page. Sign in and enter the approved Odoo base URL, database if required, and your API key. Do not put the key in chat, a support issue or this website.

    JSON-2 is the preferred transport. If unavailable, explicitly select the included addon’s HTTPS adapter. Both require the addon.

  4. Connect the MCP server in ChatGPT

    Generate manifests for your real connector URL:

    node scripts/configure.js --url https://YOUR-CONNECTOR

    Register your deployed /mcp endpoint and OAuth connection in ChatGPT, then install the packaged skill. The setup client and ChatGPT client must use the same stable identity. The package does not ship a public live endpoint.

Map your company’s custom workflow

In Odoo, an administrator opens Work Assistant → Company Mappings. A profile can replace a concept’s model, map fields and required defaults, identify ownership, define completion and enable reviewed workflow methods.

Examples are included in docs/custom-modules.md. Unknown completion stays unknown. Timesheet submission and approval are enabled only when supported methods are mapped. Wizard-based workflows require Odoo or a reviewed noninteractive adapter.

The assistant discovers structure. Your company defines meaning.

A field name alone does not explain an approval rule. Test the profile with the intended user’s real Odoo permissions.

What’s been checked

The v0.2.0 implementation passed 15 automated server/MCP tests, desktop and mobile browser checks, addon syntax/XML checks and a production dependency advisory check at delivery. These local checks used labelled sample data.

Live Odoo execution, real-provider OAuth sign-in and a ChatGPT-hosted connection have not yet been validated for your deployment. The download includes Odoo transactional tests and a Docker composition to run them on a clean staging database.

Read docs/validation.md in the package, then validate reads and one confirmed staging write before enabling production access.

Keep the deployment under your control

The current encrypted SQLite connection store is intended for a single connector instance on durable local storage. Scaling across replicas requires a shared transactional store and an appropriate encryption-key lifecycle.

Disconnect removes the active stored connection. Revoke the Odoo key separately. Your operator sets backup, audit and operation-receipt retention. Normal Odoo automation can run; external effects from custom modules may not be reversible by a database rollback.
