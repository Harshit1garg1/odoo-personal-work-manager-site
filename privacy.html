What this policy covers

Odoo Work is an independent project maintained by Harshit Garg. This page distinguishes the public informational website from a separately deployed connector. It does not claim that a developer-operated live connector is running for you.

Before connecting, identify your connector operator and review their actual hosting, access, retention and data-protection arrangements. An organization’s deployment may have additional policies.

The website and its preview

This static site provides product information, documentation and a downloadable package. It has no Odoo login form, credential store, analytics script or advertising tracker. The website loads its existing typefaces from Google Fonts; those requests are handled under Google’s privacy policy.

The product mockup and prompt outputs use fictional examples. They do not connect to Odoo or send changes to a server. Prompt tabs work locally, and copy buttons access the clipboard only when you choose to copy text.

The site is intended for GitHub Pages. The hosting provider receives normal web requests and may process request and device information under its own privacy statement. Following an external link takes you to that provider’s service and policies.

A deployed connector processes real data

When your operator deploys the connector and you connect it, the secure setup page accepts an approved Odoo URL, an optional database name and your API key. These are sent to that connector over HTTPS, not to this public website or an ordinary chat message.

The connector stores the Odoo connection encrypted using AES-256-GCM, bound to a hashed OAuth issuer/subject. The operator protects the encryption key, storage and backups. The setup browser holds its short-lived OAuth access token in sessionStorage; it does not store an OAuth refresh token.

At your request, accessible Odoo records pass through the connector to ChatGPT or the standalone dashboard. A write preview and its verified result are stored as Odoo operation records; those may contain task descriptions, timesheet details or private notes. Owner and company record rules restrict these receipts.

The connector’s audit events retain a timestamp, hashed account identifier, operation name and outcome. Its application code does not add API keys or record bodies to those events. Your operator must also configure proxies and hosting logs to avoid recording sensitive headers or bodies.

Your controls and retention

Use your own Odoo user’s key and only the permissions needed for your work. Odoo access rules and company scope apply to each operation. The connector is not designed to bypass denied access.

Disconnect deletes the active encrypted connection from the connector store. Revoke the key in Odoo as well. This does not automatically delete encrypted backups, Odoo work records, operation receipts, provider logs or ChatGPT conversations.

Backup, audit and receipt retention periods are deployment-specific. Ask your operator for their policy and deletion process before using real data. Receipts must be retained long enough to prevent duplicate writes on retries; no universal deletion timeframe is promised here.

Other services

ChatGPT processing depends on the applicable OpenAI policies and your account/workspace settings. Your Odoo host and OAuth provider have their own policies. The project does not control those providers, and this page does not replace their terms.

GitHub issues are public. Do not post API keys, passwords, cookies, employee/customer records, database dumps or confidential prompts. Use fictional reproduction data.

Questions and changes

Use project support for sanitized questions, and contact your deployment operator for account-specific access or deletion requests. The revision date above changes when this project’s description of data handling changes.
