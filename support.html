Common connection problems

A work area says “unavailable”

Check whether its Odoo app is installed, whether your user has model access and whether the company profile maps the required fields. Unavailable does not mean there are zero records.

My custom completion or approval action is missing

Your administrator needs to map a supported action and expected resulting values. A guessed stage name is not sufficient. Read docs/custom-modules.md in the package.

A write timed out

Check the result of the same operation ID before trying anything else. The write may already have committed. Retrying the same approved operation is duplicate-safe; preparing a new create can duplicate a timesheet or task.

Authentication or hostname checks failed

Ask your operator to check token issuer/audience/scopes, key expiry, TLS, the exact approved Odoo hostname and addon installation. Private-network instances also need explicit private-host approval and network connectivity.

A useful bug report includes

  • Package version, Odoo version and deployment type.
  • The feature you tried and the result you expected.
  • Clear steps using fictional tasks, users and project names.
  • A sanitized error code and whether an operation receipt was available.
  • Relevant custom mapping structure, with sensitive names and business data removed.
Public issues are public.

Never attach keys, passwords, cookies, private server URLs, employee/customer records, database backups or confidential conversation transcripts. For an account-specific or sensitive security issue, contact your deployment operator through their private channel.
